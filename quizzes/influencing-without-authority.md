# Quiz: Influencing Without Authority

## A principal engineer wants every service to adopt structured logging. Which approach is most likely to work?

- [x] Build a library with one eager team and let their results sell it.
- [ ] Write a memo explaining the benefits and mandating it by quarter end.
- [ ] Have the VP of engineering order every team to adopt it this quarter.
- [ ] Build the library alone, then announce it at the next all-hands.

**Why:** Listen first, frame the problem in terms others care about (incident time), and make the right path easy. A bare mandate is easy to ignore; a sponsor can move the last holdouts. See [[influencing-without-authority]].

## What does "pre-wiring" key stakeholders mean?

- [x] Talking to them one on one before the meeting, so concerns surface.
- [ ] Deciding privately, then announcing the result in the meeting.
- [ ] Inviting only people who already agree to the design review.
- [ ] Sending everyone the slides an hour before the meeting starts.

**Why:** Nobody likes being surprised in a group. Early conversations surface objections while they're cheap to address, without turning into backchannel decisions. See [[influencing-without-authority]].

## When is using direct authority appropriate?

- [x] In a security incident, a compliance requirement, or an outage.
- [ ] Whenever you're confident you're right about a design choice.
- [ ] Whenever a team disagrees with you twice on the same issue.
- [ ] Only after the decision has been escalated to the VP.

**Why:** Some situations need a clear decision-maker. Be clear about who's deciding and why, then return to collaborative influence afterward. See [[influencing-without-authority]].
