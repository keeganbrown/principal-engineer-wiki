# Quiz: Adopting Coding Agents as a Team

## A principal engineer is asked to "get the org using agents." What does the wiki suggest first?

- [x] A short pilot with volunteer teams, a baseline of delivery metrics, and a one-page agreement.
- [ ] A mandate that every engineer use agents daily, tracked by usage dashboards.
- [ ] Buying licenses for everyone and letting habits form on their own.
- [ ] Banning agents until a vendor certifies them as safe.

**Why:** Treat it as a change to how the team works. Pilot on real work with a baseline, and spread practice through peers. See [[adopting-coding-agents]].

## Which measure best shows whether agents are helping?

- [x] Delivery outcomes such as lead time and change failure rate, compared with a baseline.
- [ ] How many lines of code agents generated this month.
- [ ] How many engineers say they feel more productive.
- [ ] How many agent sessions each engineer started.

**Why:** Feelings are a poor measure and activity is easy to game. Measure outcomes, and track spend too. See [[adopting-coding-agents]] and [[metric-fixation]].

## A team's delivery pipeline is badly broken. Should they roll out agents now?

- [x] Fix the pipeline first; agents tend to amplify what's already there.
- [ ] Yes; agents will fix the pipeline as part of their work.
- [ ] Yes, but only for the engineers who complain most.
- [ ] No; agents don't work for teams with any legacy code.

**Why:** AI amplifies existing strengths and weaknesses. A broken pipeline gets broken faster. See [[adopting-coding-agents]].
