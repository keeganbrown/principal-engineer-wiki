# Sources: Coding with AI

Research behind the `wiki/coding-with-ai/` articles, checked 2026-11-02.
This field moves fast: re-verify these at every review and update the
articles when newer evidence lands.

| Claim | Source | Caveats |
| --- | --- | --- |
| Experienced OSS developers were 19% slower with early-2025 AI tools, predicted 24% faster, believed 20% faster afterwards. | METR, "Measuring the Impact of Early-2025 AI on Experienced Open-Source Developer Productivity" (July 2025). <https://metr.org/> | 16 developers, 246 tasks, mature repos they knew well. |
| Follow-up: returning devs −18% time (CI −38% to +9%), new devs −4% (CI −15% to +9%); METR calls the signal unreliable and is redesigning. | METR, "We are Changing our Developer Productivity Experiment Design" (2026-02-24). <https://metr.org/blog/2026-02-24-uplift-update/> | CIs include zero; selection effects (developers declining no-AI tasks). |
| AI is an "amplifier" of existing strengths and weaknesses; ~90% adoption. | DORA, *State of AI-assisted Software Development* (2025). <https://dora.dev/research/2025/dora-report/> | Survey of ~5,000 professionals. |
| DORA's delivery metrics are now five: lead time for changes, deployment frequency, change failure rate, failed deployment recovery time (formerly time to restore service), and deployment rework rate (added 2024). | DORA, "A history of DORA's software delivery metrics". <https://dora.dev/guides/dora-metrics/history/> | Checked 2026-11-01. |
| Read deny rules cover the agent's file tools and recognized shell commands, not arbitrary scripts it runs; OS-level blocking needs the sandbox. | Claude Code docs, Permissions. <https://code.claude.com/docs/en/permissions> | Vendor docs; specifics vary by tool. Checked 2026-11-01. |
| Seven capabilities amplify AI's benefits, incl. clear and communicated AI stance, healthy data ecosystems, working in small batches, user-centric focus, quality internal platforms. | DORA AI Capabilities Model (2025). <https://dora.dev/ai/capabilities-model> | Full list of seven not verified from the primary PDF; articles only name the ones confirmed. |
| Adopters of CLI coding agents merged +24.0% PRs/engineer/day (95% CI +14.5% to +33.7%); adoption spread through peers (skip-level peers +216% odds of trying). | Murphy-Hill, Butler, Savelieva (Microsoft), arXiv:2607.01418 (July 2026). <https://arxiv.org/abs/2607.01418> | One company, 16 weeks; quality, reverts, review time not measured; merged-PR counts reward small PRs; authors' employer owns GitHub. |
| AI-assisted learners of a new library scored 50% vs 67% on a quiz; largest gap on debugging; conceptual-question users scored higher. | Anthropic, "How AI assistance impacts the formation of coding skills" (2026-01-29). <https://www.anthropic.com/research/AI-assistance-coding-skills> | 52 developers, one library (Trio), quiz immediately after. |
| Explore → plan → code → commit; keep CLAUDE.md short and prune it; give the agent a way to verify its work. | Anthropic, Claude Code best practices. <https://code.claude.com/docs/en/best-practices> | Vendor guidance. |
| AGENTS.md is an open format, contributed to the Linux Foundation's Agentic AI Foundation (Dec 2025). | OpenAI, "Agentic AI Foundation". <https://openai.com/index/agentic-ai-foundation/> | Adoption figures are vendor-reported. |
| "Prompt injection" (term coined 2022) and the "lethal trifecta": private data + untrusted content + external communication. | Simon Willison, simonwillison.net (June 2025 post; "Living dangerously with Claude", Oct 2025). <https://simonwillison.net/2025/Oct/22/living-dangerously-with-claude/> | — |
| Permissions stop the agent trying; sandboxing stops an attempt succeeding. | Claude Code docs, Sandboxing. <https://code.claude.com/docs/en/sandboxing> | Vendor docs; specifics vary by tool. |
| Shared settings in `.claude/settings.json` (committed) vs `.claude/settings.local.json` (git-ignored); hooks in settings; project MCP servers in `.mcp.json`. | Claude Code docs, Settings. <https://code.claude.com/docs/en/settings> | Vendor-specific; other tools use different files. |
| Dev containers: open spec, `devcontainer.json`; increasingly used as sandboxes for coding agents, at the cost of rebuild time. | Development Containers spec <https://containers.dev/implementors/spec>; Thoughtworks Technology Radar, "Dev containers" (2026). <https://www.thoughtworks.com/radar/tools/dev-containers> | — |
| MCP tool poisoning: malicious tool descriptions/outputs inject instructions; vet, pin, scope servers. | Cloud Security Alliance, Agentic MCP Security Best Practices (draft). <https://labs.cloudsecurityalliance.org/agentic/agentic-mcp-security-best-practices/> | Draft guidance; many CVE counts are vendor-reported. |
| After firm-level agent adoption: lines of code +44.0%, commits +36.0%, PRs opened +35.7%, PRs merged +26.0% (only ~62.7% of extra PRs merged); Jira issues resolved +13.7% (borderline), epics +18.0%, gains above 30.7% ruled out; no change in predicted issue size or bug reports; no detectable employment effect. Review: submission-to-approval +56.1%, backlog wait +59.9%, active review +58.5%, comments per change +38.6%. Engineers spend 30–40% of time writing code. | Fiona Chen and James Stratton (Harvard), "Artificial Intelligence in the Firm: Bottlenecks in Software Production", job market paper, current version 2026-11-01 (first 2026-01-07). Data from Jellyfish. <https://fion.ac/jellyfish.pdf>; coverage: InfoQ (2026-10-22) <https://www.infoq.com/news/2026/10/jellyfish-ai-productivity/> | Working paper, not peer reviewed. Staggered difference-in-differences on firm-level adoption timing, not randomized; 655 firms, 720,542 workers, Jan 2021–Aug 2026. InfoQ's figures (718 firms, PRs +23%, review +49%) come from an earlier version; the article uses the current one. |
| Enterprise "2x" mandate, 802 developers (564 in estimation sample), 196,212 PRs: throughput up ~12% at adoption; adoption effect +0.13 to +0.35 log points (~13–42%) depending on estimator; per-reviewer load 2.0×; automated review ~19% → 84% of PRs; substantive human review ~39% → 21%; AI-authored PRs had lower revert probability. | Hao He, Shyam Agarwal, Yegor Denisov-Blanch, Pavel Azaletskiy, Sanmi Koyejo, Bogdan Vasilescu (CMU, Stanford), "AI Writes Faster Than Humans Can Review: A Longitudinal Study of an Enterprise 2x Mandate", arXiv:2607.01904 (v2 2026-10-27). <https://arxiv.org/abs/2607.01904> | One firm, non-randomized adoption, uncapped AI budgets (an upper bound); direction more reliable than magnitude; short-horizon quality proxies; no CIs in text. |
| Committed AI config files (RAMP maturity model): agents raise commits 28–38% regardless of maturity; in agent-first repos cognitive complexity +52.70% without committed config vs +26.68% with it; static-analysis warnings +24.08% vs +14.04%; 73.8% of config artifacts committed once and never modified. | Yegor Denisov-Blanch, Shyam Agarwal, Pavel Azaletskiy, Hao He, Rylan Schaeffer, Brando Miranda, Bogdan Vasilescu, Sanmi Koyejo (Stanford, CMU, Grid Dynamics), "A Few Pages of Markdown: Committed AI Configuration and Lower Quality Cost after Coding-Agent Adoption", ASE '26, arXiv:2608.25241 (v2 2026-09-14). <https://arxiv.org/abs/2608.25241> | Observational (difference-in-differences on 509 treated repos); discipline may explain both config and quality; SonarQube metrics are proxies; ~14-month window; authors call it hypothesis-generating. |
| Agent users (Aider editing their code) were faster and more accurate on the initial task than chatbot users but scored significantly lower on comprehension (p<0.002, d>0.80); similar accuracy on a later no-AI extension task; agent users reported less effort and less ownership but rated the tool more helpful. | Nishant Balepur, Connor Baumler, Valerie Chen, Eunsol Choi, Rachel Rudinger, Jordan Boyd-Graber (UMD, NYU, CMU), "(Im)Paired Programming: Coding Agents Improve Productivity but Harm Understanding", arXiv:2607.26375 (2026-07-29). <https://arxiv.org/abs/2607.26375> | In-progress preprint; 54 CS students, two website tasks, short-term only. |
| Autonomous agent loops found in 217 open-source repos (from 36,710 mined); nearly all commit loop configuration, almost none commit the state files practitioners recommend; recommended parts: scheduled or event trigger, machine-checkable stop condition, persistent state, verifier, token budget, human escalation point. | Jai Lal Lulla, Vahram Nersesyan, Seyedmoein Mohsenimofidi, Christoph Treude, Sebastian Baltes, "Loop Engineering: Building Blocks, Adoption, and Impact", JAWs@ASE 2026, arXiv:2608.21884 (v3 2026-10-22). <https://arxiv.org/abs/2608.21884> | Workshop paper; gray literature offers no systematic evidence of benefits; detection is heuristic; the controlled experiment is proposed, not run. |

## Read but not cited yet

- METR (Amy Deng), "Analyzing coding agent transcripts to upper bound productivity gains from AI agents" (2026-02-17). <https://metr.org/notes/2026-02-17-exploratory-transcript-analysis-for-estimating-time-savings-from-coding-agents/> Estimated time-savings factors of ~1.5× to ~13× from 5,305 Claude Code transcripts by 7 staff, highest for those running parallel agents. METR calls it a soft upper bound, not a productivity multiplier; one month, one organization.
- Raida and Hou, "Early Adoption of Agentic Coding Tools by GitHub Projects", arXiv:2607.14037 (July 2026). <https://arxiv.org/abs/2607.14037> Median repo had 1–2 agentic PRs in three months across 2,361 popular repos; single-human oversight dominated. Early snapshot.
- LeadDev reports DORA will not publish a 2026 *State of AI-assisted Software Development* report (announced 2026-09-03). <https://leaddev.com/?p=36788> Not yet confirmed on DORA's own channels; the 2025 report remains the latest.
